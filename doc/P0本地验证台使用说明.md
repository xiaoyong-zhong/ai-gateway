# P0 本地验证台使用说明

## 启动

先启动 P0 Docker 测试环境并确认 `.env.p0-test` 已初始化，然后在仓库根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Start-P0Console.ps1
```

控制台会监听 `127.0.0.1:18770` 并打开浏览器。关闭时在启动它的 PowerShell 窗口按 `Ctrl+C`。如端口冲突，可以使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Start-P0Console.ps1 -Port 18771
```

控制台使用 Python 标准库，无须安装 Node.js、前端依赖或额外容器。网页服务绑定回环地址，并限制 Host / Origin；不要把它改成 `0.0.0.0` 监听。

正常启动后打开 `http://127.0.0.1:18770/`。更新控制台代码后，先在启动控制台的 PowerShell 窗口按 `Ctrl+C` 停止旧进程，再重新运行启动命令；浏览器若仍显示旧版页面，使用 `Ctrl+F5` 强制刷新。

## 页面能验证什么

- 容器、健康状态、端口绑定、测试域名解析、Higress → LiteLLM 模型目录和 Prometheus 抓取状态。
- 缺失/错误/当前/兼容 Key、错误 Host、Consumer Key 直连 LiteLLM、LiteLLM 无 Key 直连。
- 从经过 Higress 的 LiteLLM `/v1/models` 目录读取模型别名；默认选择 P0 基准 Qwen `my-qwen3.6-27b`。其他已配置别名可用于单项 Chat / SSE / Responses / 工具调用检查，但页面与服务端都会要求先确认真实调用风险；完整 P0 验收仍固定使用基准 Qwen。
- 最近 7 天最多 30 条 LiteLLM SpendLogs，展开单条可查看请求正文、响应正文、Token 与耗时；认证凭据字段显示为 `[REDACTED]`。
- 一键运行 `scripts/run_p0_acceptance.py --verify-rate-limit --timeout 120` 完整 P0 自动验收，覆盖 RPM / TPM、SpendLogs、凭证泄露检查、7 天日志留存、Envoy 指标、IP 策略及 Provider DNS 分类。
- 展示最近一次自动验收报告的安全摘要，并可打开原始 Markdown 报告。

除模型目录、认证与运行状态检查外，Chat / SSE / Responses / 工具调用都会实际访问当前选择的模型并产生 Token。非基准模型可能路由到不同 Provider 或产生实际费用，请只选获准测试的别名。勾选确认只表示操作者确认调用风险，不代表系统已核实 Provider 归属或费用。完整验收不会受页面模型选择影响，仍调用基准 Qwen；TPM 测试会短暂使用 1 Token 测试阈值，脚本结束时恢复正常配置并清理 P0 专用 Redis 限流数据库。

## 建议验证顺序

1. 启动后先看“P0 服务”和“网关链路”卡片；若状态异常，点击“刷新状态”并先处理未就绪服务。
2. 点击“认证与路由”中的认证检查，验证当前 Key、兼容 Key、错误 Key / Host 与 LiteLLM 直连隔离。
3. 模型选择器默认是 `my-qwen3.6-27b`。可先点“模型目录”确认网关当前提供的别名；目录查询不调用上游模型。
4. 选择要验证的模型，再运行 Chat、SSE、Responses 或工具调用。基准模型无需额外确认；其他模型必须勾选风险确认。每次接口验证都会真实调用所选模型并产生用量。
5. 到“用量与监控”选择统计区间，查看请求与 Token 汇总；需要核对单次 Prompt / Response 时，到“最近调用日志”手动刷新并展开对应记录。
6. 只有需要执行全套 P0 回归时才点“运行完整 P0 验收”。此操作会调用基准 Qwen，并短暂修改测试限流阈值后恢复；完成后可在同一区域查看最新验收报告。

## 用量与监控

在“用量与监控”卡片的“统计区间”下拉框中选择最近 15 分钟、1 小时、24 小时或 7 天。它们是滚动时间窗，不是任意起止时间的自定义查询。卡片每 15 秒自动刷新；切换区间后也会立即重新汇总。

- **模型用量（LiteLLM SpendLogs）**：统计所选时间窗内的模型请求总数、成功/失败数、输入 Token、输出 Token、总 Token，并列出 Token 用量最多的 10 个模型。数据在模型请求完成并写入 LiteLLM 数据库后才会出现。
- **网关监控（Higress / Prometheus）**：统计同一时间窗内经过 Higress 的请求数、2xx、4xx、5xx 数和平均请求延迟。Prometheus 抓取间隔配置为 15 秒，指标显示可能有一个或多个抓取周期的延迟。
- **两种请求数口径不同**：LiteLLM 只统计进入模型服务并写入 SpendLogs 的调用；Higress 还会统计认证拒绝等未到达 LiteLLM 的网关流量。因此两边的请求数不应要求相等。
- **费用**：单价未确认，Spend 金额不作为费用估算、预算控制或财务结算依据。

顶部的“最近验收”只表示最近一次 P0 自动验收的通过/失败数量，与所选时间窗的运行用量无关。容器健康和服务状态需要点击页面顶部的“刷新状态”；“最近调用日志”是独立的最近 7 天明细列表，需手动刷新，不随统计区间切换。

## 密钥和日志

当前 Consumer Key 与兼容期 Key 从 Git 忽略的 `.env.p0-test` 由本机 Python 服务端读取，不在页面显示，也不会写入服务访问日志。客户端请求记录依 P0 既定策略进入本机 LiteLLM SpendLogs；页面本身不会保存凭证。错误响应在显示前会对本地已知密钥做脱敏。

“最近调用日志”只读查询 P0 专用 PostgreSQL 中 7 天内的记录，默认折叠正文，点击一行后再显示请求/响应 JSON。数据库中的 `api_key` 列不向页面返回；正文里的 Authorization、API Key、Token、Secret、Password 等凭据字段会屏蔽。日志内容仍可能包含用户 Prompt 或模型输出，所以页面只监听 `127.0.0.1`，仅供本机测试人员查看。

页面不提供 Key 轮换、配置回滚、生产部署或 IP 白名单启用操作。这些操作需要运维决策或专门的变更流程，不是日常功能探测。

## 状态边界

- Qwen 单价未知：LiteLLM Spend 不作为费用估算或财务结算。
- IP 限制保持未应用：等待批准的具体 CIDR。
- Provider DNS 地址本身不能证明网络属于内网/专线。
- Higress AI Statistics 不作为本地 P0 验收来源。
- 本地验证通过不等于服务器预发布或生产验收通过。

决策细节见 [P0 上线前决策清单](P0上线前决策清单-2026-09-22.md)，自动验收仍以 [Run-P0EndToEnd.ps1](../scripts/Run-P0EndToEnd.ps1) / `scripts/run_p0_acceptance.py` 生成的报告为准。
