# P1 本地验证台使用说明

## 1. 适用范围

这是 P1 Docker 测试环境的本地验证台，不是生产管理后台。它用于快速确认 Higress、Mapper、LiteLLM、应用 Key、模型授权、用量和日志链路是否可用。

当前 P1 采用一个最小化的测试组织 `org-p1-test`：已经实现“组织模型白名单”和“应用模型子集”校验，但完整的组织树、SSO、用户、角色和 RBAC 仍不在 P1 范围内。

## 2. 启动环境

在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Initialize-P1TestEnvironment.ps1 -Start -Provision
```

初始化脚本会在 Docker 环境启动并完成配置后，在宿主机后台启动 P1 Console 并打开浏览器。默认验证台地址为 `http://127.0.0.1:28770/`；如果浏览器没有自动打开，直接访问该地址即可。

确认 hosts 文件包含：

```text
127.0.0.1 ai-gateway-p1-test.local
```

需要手动重新打开页面时，可以执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Start-P1Console.ps1
```

控制台只监听宿主机 `127.0.0.1`，不会对外网开放。修改前端或后端代码后重启验证台，并在浏览器使用 `Ctrl+F5`。

## 3. 客户端接入信息

在“应用与 LiteLLM 原生策略”表格中点击某个应用的“接入信息”。默认只显示脱敏 Key；点击确认后才显示本机测试用的完整 Higress Consumer Key。

CCSwitch 填写：

- 请求地址：`http://ai-gateway-p1-test.local:28080`
- API Key：当前应用的 Higress Consumer Key
- 上游格式：OpenAI Chat Completions

OpenAI SDK 或直接调用 HTTP 时使用：

```text
http://ai-gateway-p1-test.local:28080/v1
```

模型目录、Chat、Responses、Embedding、Image 的具体路径会在接入信息面板中显示。不要把 LiteLLM Master Key、Provider Key 或 Mapper 派生 Key 填到客户端。

## 4. 模型权限规则

模型权限按以下层级生效：

```text
config/litellm.p1-test.yaml 中的模型目录
        ↓
当前测试组织允许模型（管理员设置）
        ↓
应用允许模型（创建应用的使用者选择）
```

当前 P1 已加载 `config/litellm.yaml` 中的 8 个模型，包括 Chat、Embedding 和 Image 类型。模型是否真正可调用，以 LiteLLM `/v1/models` 的实际返回为准；修改 LiteLLM 配置后必须重启 P1 LiteLLM 容器。

注意：客户端使用某个应用的 Higress Key 请求 `/v1/models` 时，LiteLLM 可能只返回该应用授权的模型子集；组织面板和创建应用使用的是全局 P1 模型目录，真实请求验证下拉框则按当前选中的应用显示其子集。

### 4.1 管理员设置组织模型

在“当前组织模型权限”面板多选模型并保存。后端接口为：

```text
POST /api/organization/policy
```

请求体中的 `allowed_models` 必须来自当前 P1 LiteLLM 配置，不能提交任意字符串。

收紧组织权限前，必须先把现有应用的策略改成新组织集合的子集。系统发现已有应用仍使用被移除模型时，会拒绝保存并列出冲突应用，避免运行中的应用被静默撤权。

### 4.2 创建应用时选择模型

点击“创建应用”，模型选择框支持多选。可选项只显示当前组织允许且已经在 P1 LiteLLM 中激活的模型。后端还会再次校验，应用提交组织外模型时会拒绝创建。

### 4.3 修改已有应用策略

点击应用行的“策略”，在“允许模型”多选框中选择该应用的模型子集，同时设置 RPM、TPM 和最大并发。保存会调用现有的 `Manage-P1Application.ps1 -Action SetPolicy`，不是前端维护第二套状态。

## 5. 快速验证流程

1. 查看顶部服务状态、网关链路和模型目录。
2. 在应用表格中查看应用、模型子集、限流策略和 Key 状态。
3. 在“真实请求验证”中选择应用和模型，执行 Models、Chat、SSE、Responses、Tools、Embedding 或 Image 验证。
4. 使用“未授权模型”按钮确认越权请求返回预期拒绝结果。
5. 在“用量与日志”选择 15 分钟、1 小时、24 小时或 7 天窗口，查看 LiteLLM SpendLogs 的请求数、Token、模型分布和正文日志。
6. 需要运行完整自动化检查时，再启动专项验收脚本；这些脚本会进行真实请求或临时修改测试策略，页面会要求二次确认。

## 6. 专项验收脚本、快照与回滚

专项验收脚本是自动化技术检查，不是客户端调用入口：

- P1-0 技术闸门：检查 Key-H、Higress、Mapper、Key-L、LiteLLM 的安全链路。
- 原生策略：检查 LiteLLM 的 RPM 等策略。
- Mapper：检查 HMAC 派生、请求校验和拒绝路径。
- 协议矩阵：检查 Chat、SSE、Responses、Tools、TPM 和并发组合。
- 延迟基准：分别统计 Mapper、LiteLLM 和完整网关链路耗时。

快照、发布、回滚只针对本地 P1 Higress 测试配置：

- 快照：保存当前配置到 `runtime/p1-test/higress/snapshots/`。
- 发布：把仓库中的 P1 Higress 配置应用到本地测试容器。
- 回滚：从选定快照恢复本地测试配置。

执行发布或回滚前应先创建快照；这些操作不等于生产发布，也不会提交 Git。

## 7. 数据、日志和边界

- 请求正文日志默认开启，仅保留在本机 P1 测试数据库，默认保留 7 天，不得提交到仓库。
- 用量统计优先复用 LiteLLM SpendLogs；LiteLLM Spend 在 P1 仅作为估算和观测值，不作为财务结算依据。
- Higress 页面展示的累计请求指标来自 Envoy 原生计数器，统计范围是当前 Higress 进程启动以来，不受上方 LiteLLM 时间区间选择影响；Higress 重启后计数会重新开始，不冒充任意时间段的精确财务统计。
- P1 使用独立 Compose、网络、卷、域名和测试 Key，不应直接连接现网。
- P1 尚未提供生产级组织树、用户、SSO、RBAC、多副本高可用、生产 CIDR/mTLS、完整审计审批和生产密钥托管。

## 8. 相关文件

- `config/p1-test/apps.json`：应用非敏感清单和应用模型子集。
- `config/p1-test/organization-model-policy.json`：当前测试组织允许模型。
- `config/litellm.p1-test.yaml`：P1 LiteLLM 模型目录。
- `gateway/p1-console/server.py`：验证台 API、组织/应用模型权限后端校验。
- `gateway/p1-console/static/index.html`、`static/app.js`：验证台页面和交互。
- `scripts/New-P1Application.ps1`：创建应用并配置 Virtual Key、Higress 和验证。
- `scripts/Manage-P1Application.ps1`：查询、策略更新、禁用、恢复、对账和 Key-H 生命周期管理。
