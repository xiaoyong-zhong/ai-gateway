# P0 本地 Docker 测试环境操作手册

本环境与既有 `deploy/docker-compose.yml` 完全隔离：独立网络、PostgreSQL、Redis、Higress 数据目录、LiteLLM Master Key 和 Higress Consumer Key。不会占用现有 `4000`、`8001`、`8080` 或现网数据卷。

## 固定访问链路

```text
CCSwitch
  -> http://ai-gateway-test.local:18080/v1
  -> Higress Key Auth（Higress Consumer Key）
  -> Higress AI Proxy（注入 P0 LiteLLM Master Key）
  -> LiteLLM（my-qwen3.6-27b -> 内网 Qwen3.6-27B）
  -> 内网模型服务
```

客户端不可使用 LiteLLM Master Key；CCSwitch 的 API Key 必须是 `.env.p0-test` 中的 `P0_HIGRESS_CONSUMER_KEY`。

## 首次启动

在仓库根目录的 PowerShell 中执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/Initialize-P0TestEnvironment.ps1 -Start
```

脚本首次执行会生成本机私有 `.env.p0-test`，其中的密钥不会输出、不会进入 Git。它会在本地旧 Higress 配置存在时，仅为短暂切换窗口导入旧 Consumer Key；该旧 Key 仅保存在忽略文件中。

以管理员权限将下列一行加入 Windows hosts 文件 `C:\Windows\System32\drivers\etc\hosts`：

```text
127.0.0.1 ai-gateway-test.local
```

然后在 CCSwitch 配置：

| 字段 | 值 |
| --- | --- |
| 请求地址 | `http://ai-gateway-test.local:18080` |
| API Key | `.env.p0-test` 的 `P0_HIGRESS_CONSUMER_KEY` |
| 模型 | `my-qwen3.6-27b` |

本机验证端口：Higress Gateway `18080`、Higress Console `18001`、LiteLLM UI/API `14000`；均只绑定 `127.0.0.1`。

## 验收

hosts 生效后执行：

```powershell
# 完整端到端验收（推荐）
powershell -ExecutionPolicy Bypass -File scripts/Run-P0EndToEnd.ps1

# 或分步执行：
powershell -ExecutionPolicy Bypass -File scripts/Test-P0Gateway.ps1
powershell -ExecutionPolicy Bypass -File scripts/Verify-P0Observability.ps1
powershell -ExecutionPolicy Bypass -File scripts/Verify-P0AiStatistics.ps1
powershell -ExecutionPolicy Bypass -File scripts/Test-P0IpRestriction.ps1
```

未改 hosts 时，可使用显式 Host 头完成同等测试：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/Test-P0Gateway.ps1 -UseExplicitLocalHost
powershell -ExecutionPolicy Bypass -File scripts/Run-P0EndToEnd.ps1 -UseExplicitLocalHost
```

限流穷尽验证会消耗当前分钟的测试配额，按需执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/Test-P0Gateway.ps1 -VerifyRateLimit
powershell -ExecutionPolicy Bypass -File scripts/Run-P0EndToEnd.ps1 -VerifyRateLimit
```

验收范围：缺失/错误 Consumer Key 返回 401；新 Key 与短暂保留的旧 Key 均可访问；`my-qwen3.6-27b` 的非流式和 SSE 流式请求返回文本和 usage；LiteLLM `SpendLogs` 存在请求体、响应体、Token 和估算 Spend，同时不包含 Consumer、Master 或 Qwen Provider Key；Higress 每 Consumer 10 RPM 返回 429；AI Statistics 通过 Prometheus 端点采集 Token/延迟指标；IP Restriction 白名单配置正确（FAIL_CLOSE 策略）。

## Key 轮换

先创建新 Key 并保留前一个 P0 Key：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/Rotate-P0HigressConsumerKey.ps1
```

从 `.env.p0-test` 读取新的 `P0_HIGRESS_CONSUMER_KEY` 配置到 CCSwitch，确认请求成功后，移除旧 Key：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/Rotate-P0HigressConsumerKey.ps1 -RetireLegacy
```

P0 始终最多接受两个 Key；轮换脚本不会在终端显示密钥。

## 配置管理与回滚

修改 Higress 配置前执行备份：

```powershell
# 修改前备份
powershell -ExecutionPolicy Bypass -File scripts/Backup-P0Config.ps1 -Message "Before adding IP restriction"

# 应用 IP Restriction（可选）
docker compose --env-file .env.p0-test -f deploy/docker-compose.p0-test.yml exec -T higress python3 -X utf8 /p0-scripts/bootstrap_higress_p0.py --env-file /p0-env/.env.p0-test --resource-file /p0-config/resources.json --include-ip-restriction

# 查看可用版本
powershell -ExecutionPolicy Bypass -File scripts/Rollback-P0HigressConfig.ps1 -ListVersions

# 回滚到指定版本
powershell -ExecutionPolicy Bypass -File scripts/Rollback-P0HigressConfig.ps1 -Version "20260921-120000"

# 回滚到上一个版本
powershell -ExecutionPolicy Bypass -File scripts/Rollback-P0HigressConfig.ps1 -PreviousVersion

# 生成部署报告
powershell -ExecutionPolicy Bypass -File scripts/Generate-P0DeployReport.ps1
```

备份文件存储在 `config/higress/p0-test/backups/`，变更日志记录在 `config/higress/p0-test/CHANGELOG.md`。

## 日志、限流与留存

- LiteLLM 的 `store_prompts_in_spend_logs: true` 保存请求/响应正文；`P0_LOG_RETENTION_DAYS=7`。
- Higress AI Proxy 会生成内部 `x-hi-original-auth` 头；P0 的 `transformer` 在其后删除该头，防止 Consumer Key 被 LiteLLM 正文日志记录。不得删除此脱敏资源后仍开启正文日志。
- `log-pruner` 每 24 小时删除测试数据库中超过保留期的 `LiteLLM_SpendLogs`。测试数据库仅限本机，不得提交或复制到生产。
- Redis 支持 Higress `cluster-key-rate-limit`（10 RPM/Consumer）和 `ai-token-ratelimit`（20,000 TPM/Consumer）。两者均为 P0 低阈值测试值。
- LiteLLM Spend 是技术估算，不是财务结算。

## 停止

停止容器但保留测试数据：

```powershell
docker compose --env-file .env.p0-test -f deploy/docker-compose.p0-test.yml down
```

不要将此测试环境的域名、Key、阈值、正文日志策略或卷直接复制到生产。生产域名、TLS、CIDR、留存期和阈值须在上线阶段重新确认。
