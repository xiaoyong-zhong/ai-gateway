## 1.1 实施与验收结果（2026-09-22）

本次只改动本地独立 `api-gateway-p0-test` Compose 项目；未操作现网容器、现网卷、现网网络或当前 CCSwitch Key。最近一轮完整自动验收报告保存在 Git 忽略的 `runtime/p0-test/reports/`，报告仅记录 request_id、计数和脱敏结论，不含 Key 或 Prompt/Response 正文。

- 新增 P0 Prometheus 旁车，通过 `network_mode: service:higress` 抓取 Envoy `15000` 原生指标；宿主机仅发布 `127.0.0.1:19090`，Envoy 管理端口不再发布。
- 禁用 `p0-ai-statistics` 的实际匹配规则；本地 P0 以 LiteLLM SpendLogs 统计模型用量、以 Envoy 原生 Prometheus 统计入口请求数/状态码/延迟。AI Statistics 不会再以空指标或退出码 0 伪报通过。
- 日志保留器增加数据库暂不可用重试与健康检查；用 8 天前/1 天内的合成 SpendLog 验证“删除超期、保留未超期”，最后清理合成行。
- 端到端验收以 `scripts/run_p0_acceptance.py` 为唯一功能事实来源；PowerShell 仅为兼容入口。它覆盖 Host、认证、Chat、SSE、Responses、自动工具调用、RPM、TPM、SpendLog、脱敏、留存、Prometheus 与 IP 延期状态。
- `p0_release.py` 用 release manifest 备份 P0 管理文件和本机私密恢复副本。已完成实际 `p0-ai-statistics priority 900 → 901 → 900` 演练：变更已应用到 Higress 运行态，回滚后文件和运行态均恢复 900，LiteLLM 健康。

未决项不应被掩盖：Qwen Provider 域名在 LiteLLM 容器中解析为 `124.128.58.201`，仅凭此结果不能证明其网络路径是内网；Qwen 单价未知，Spend 无法成为费用估算；IP 仍等待运维给出具体 CIDR；Key 轮换脚本已修复但按保护边界未对当前 CCSwitch Key 执行实际轮换。

## 2. 已固定范围与保护边界

以下项目沿用已确认决策，不在本方案中重新扩大范围：

- 只在本机独立 P0 Docker 环境工作；不操作现网，不复用或更改现网容器、卷、网络和密钥。
- 测试入口保持 ai-gateway-test.local，宿主机端口 18080；同机 CCSwitch 使用 Higress Consumer Key。LiteLLM Master Key 不交给客户端。
- 当前 Consumer Key 和短期兼容 Key 不在本次方案编写阶段轮换。需要测试轮换时，先有恢复点，再在本地测试环境验证。
- 基线模型只使用已指定的 my-qwen3.6-27b；不发起 DashScope、DeepSeek、Agnes 等外部模型调用。
- Prompt/Response 正文日志继续仅写本地 P0 LiteLLM/PostgreSQL 数据，目标保留 7 天；报告不包含请求正文、响应正文或任何 Key。
- IP Restriction 保持未应用，直到运维给出明确的测试/生产 CIDR。现有宽泛 RFC1918 白名单不得直接视为已批准策略。
- P0 优先复用 Higress、LiteLLM 已有功能，不新增自研计费、日志或指标服务。
- 不把 P0 扩展成按用户/组织结算、每日/总额度、学校 SSO 或财务账本。若后续确定这些是 P0 必需项，需单独确认边界及额度口径。

## 3. 分工作包修复方案

### P0-1：统一测试入口并清除文档漂移

当前实现：

- 独立 Compose 项目和 P0 网络、命名卷已存在。
- Gateway、LiteLLM 对宿主机的发布端口绑定 127.0.0.1；数据库和 Redis 没有发布宿主机端口。
- 本机域名解析到 127.0.0.1；当前有效入口是 http://ai-gateway-test.local:18080，CCSwitch 请求实际访问 /v1/...。

需修复：

1. 统一 P0 方案、操作手册、结项模板中的入口说明。最终方案现存的 8080、ai-test.local 等描述与当前 P0 运行态不一致。
2. 在 CCSwitch 操作说明中明确服务地址填写域名和 18080，Key 填 Higress Consumer Key；同机 hosts/DNS 已生效时无需额外伪造 Host 头。
3. 自动测试增加错误 Host 测试，确认不会落入默认路由并访问 LiteLLM；检查对应请求没有产生上游 SpendLog。
4. 继续保持 P0 管理端口和直连 LiteLLM 端口只绑定宿主机回环地址。不要为方便测试改成 0.0.0.0。

涉及文件：deploy/docker-compose.p0-test.yml、config/higress/p0-test/resources.json、doc/P0本地测试环境操作手册.md、doc/P0阶段实施方案-最终版-2026-09-21.md、doc/P0结项报告-模板.md。

完成标准：

- 从本机 CCSwitch 按文档配置可完成模型列表与 Chat；DNS、端口、Host 路由与 Key 入口一致。
- 正确 Host 请求走 P0 路由；错误 Host 不触达 LiteLLM。
- Compose 的所有管理和数据服务宿主机绑定边界仍为 localhost，数据库和 Redis 不向宿主机发布。

风险与依赖：生产真实内网域名、TLS 与服务器 DNS 仍是后续发布决策，不在本地 P0 中预设。

4. 记录 LiteLLM 14000 是仅本机管理/排障入口，不是客户端入口；客户端必须使用 Higress Consumer Key 和 18080 入口。

- 故障闭锁验证不能通过破坏当前环境完成；若需故障注入，应在可恢复的独立 P0 副本或临时资源中进行。

风险与依赖：Higress 插件启动失败测试可能影响路由，必须先完成 P0-7 恢复能力，或只在副本中执行。

### P0-3：让 Key 轮换具备失败恢复能力

当前实现：

- 当前 Key 由加密随机数生成；当前与旧 Key 在 Higress 中同时可用；.env.p0-test 已被 Git 忽略。
- 轮换脚本先覆写环境文件，再运行 Higress bootstrap；没有可靠地检查外部 docker 命令的退出码，也没有失败时自动恢复旧文件与旧运行态的完整闭环。

需修复：

1. 轮换前建立本地恢复快照；快照只放 Git 忽略的 P0 私有目录，不写入报告。
2. 轮换后显式检查 bootstrap 退出码、运行态资源和新旧 Key 请求结果；任一步失败时恢复旧环境文件并重新应用旧凭证，失败必须非零退出。
3. 只有验证新旧 Key 均可用后，才提示更新 CCSwitch；退休旧 Key 时验证新 Key 200、旧 Key 401。
4. 限制兼容窗口最多两个 Key；重复轮换只保留当前 Key 和紧邻的上一个 Key。
5. 不在本次实现前对正在使用的 Key 执行真实轮换。轮换脚本可先用独立测试凭证或可恢复的 P0 临时副本测试。

涉及文件：scripts/Rotate-P0HigressConsumerKey.ps1、scripts/Initialize-P0TestEnvironment.ps1、scripts/bootstrap_higress_p0.py、.gitignore。

完成标准：

- 正常轮换、旧 Key 兼容、退休旧 Key三种状态都经运行态验证。
- 模拟 Higress 应用失败时，脚本返回非零，磁盘与运行态回到同一版本；日志中无密钥。

风险与依赖：写入 .env 与 Higress 运行态需要保持一致；不能把“环境文件已生成”当作“轮换已生效”。

需修复：

涉及文件：config/litellm.yaml、gateway/litellm/callback/qwen_responses_compat.py、scripts/test_p0_gateway.py、doc/P0阶段实施方案-最终版-2026-09-21.md。

完成标准：

风险与依赖：Responses 和工具调用需要与最终接受的 P0 API 范围一致；工具调用若不属于 CCSwitch 试点需求，可明确后置。

### P0-5：把 Token、Spend、正文日志与 7 天保留验清

当前实现：

- LiteLLM 内置 store_prompts_in_spend_logs 已开启；本地 SpendLogs 有请求、响应正文和 Token；敏感凭证查询为 0。
- 本轮 Qwen 测试 Spend 合计为 0。当前模型配置没有显式价格项，因此不能把 0 当成“已经校验通过的费用估算”。
- .env.p0-test 配置保留天数为 7，log-pruner 当前运行，但尚未验证超期行确实被删除；其容器历史有 2 次重启。
- 当前验证脚本按最近时间窗口汇总，可能拿旧记录证明新测试通过，不能证明每次本轮调用都写入。

需修复：

1. 为每次验收请求产生测试开始时间或测试 ID，保存响应 request_id；用该测试窗口/ID 验证对应 SpendLog，避免旧行造成假通过。
2. 除正文、Token 外，核验模型、响应结果、耗时、流式 usage 与失败请求日志。不得在终端/报告中输出正文、Key 或数据库敏感行。
3. 确认 Qwen 的成本口径。如果模型所有者提供输入/输出估算单价，则配置 LiteLLM 可用的模型成本映射，并用固定 Token 样本验证 estimated spend；如果没有可用价格，记录为未知/不可估算，不用 0 伪装估算。
4. 用本地隔离测试数据实测 7 天策略：超期测试行被清理，未超期测试行保留；不查询或删除非 P0 数据。
5. 检查 log-pruner 对数据库重启/暂不可用的恢复行为，确保容器稳定重试并提供可诊断状态。
6. P0 正文日志只存本地测试 PostgreSQL 卷，保留期 7 天，日志/报告不得提交 Git。生产环境留存期限和访问权限仍需安全/运维确认。
7. 按当前固定范围，P0 Spend 不是财务结算；日/总预算不是现有 RPM/TPM 的同义词。若需业务预算阻断，先单独确定价格来源、主体归属和额度，再评估 LiteLLM 原生 Budget；不新增自研计费。

涉及文件：config/litellm.yaml、scripts/Verify-P0Observability.ps1、deploy/docker-compose.p0-test.yml、doc/P0阶段实施方案-最终版-2026-09-21.md。

完成标准：

- 每次指定测试调用能对应到本轮 SpendLog；正文策略、Token、耗时、结果、敏感字段脱敏都可核验。
- Spend 有明确的“估算值”或“未知/不可估算”状态，不将无价格配置的 0 视为通过。
- 7 天保留有正反向测试证据；日志只留在 P0 本地数据库。

风险与依赖：若要得到非零估算值，需要模型所有者确认价格口径；本方案不擅自填入价格，也不把估算值当成财务结算。

### P0-6：完成原生限流验收，解决指标口径，保留 IP 决策门

当前实现：

- Higress Redis 驱动的 10 RPM/Consumer 和 20,000 TPM/Consumer 配置已应用；此前有 RPM 返回 429 的验证记录，本轮没有再次打满。
- TPM 尚无独立触发证据。
- p0-ip-restriction 不在当前运行态。现有配置文件只在传入 include-ip-restriction 时应用；这是符合“CIDR 待运维确认”的当前状态。
- ai-statistics WasmPlugin 虽已配置，但本地 all-in-one Docker 的 Prometheus 端点只在 Higress 容器回环地址可用，主机端口映射失败，且无 ai_ 指标行。

需修复：

1. 用独立、可恢复的测试阈值或测试 Consumer 验证 TPM 超限返回 429；不要为触发 20,000 TPM 而向基线 Qwen 发送超大请求。恢复后核验 20,000 TPM 配置未被改变。
2. 限流验收分别记录 RPM 与 TPM；用例执行后只清理 P0 Redis 对应数据库/测试键，不能清其他业务 Redis 数据。
3. IP Restriction 继续保持未应用。运维给出具体 CIDR 后，替换全部 RFC1918 宽范围，测试白名单请求通过、非白名单来源返回 403；不得只通过伪造 X-Forwarded-For 得出结论。
4. 按已确认方案不开发自定义指标服务：LiteLLM SpendLogs 负责 Token/Spend/模型/调用记录，Envoy Prometheus 指标负责入口 QPS、状态码和延迟。Higress AI Statistics 在当前 all-in-one Docker 不产出指标，标为不用于本地 P0 验收；服务器部署后如要启用，需单独实测。
5. 如果确认必须使用 AI Statistics，先定位官方插件/当前目标部署模式的支持条件及 metrics bind 地址，在隔离环境验证 Prometheus 抓取到真实非零 Token/延迟指标；不能以插件资源存在、HTTP 200 或退出码 0 作为 PASS。

涉及文件：config/higress/p0-test/resources.json、config/higress/p0-test/ip-restriction.json、scripts/bootstrap_higress_p0.py、scripts/Test-P0IpRestriction.ps1、scripts/Verify-P0AiStatistics.ps1、deploy/docker-compose.p0-test.yml。

完成标准：

- RPM、TPM 各有独立行为测试；IP 状态明确为“因等待运维 CIDR 而未启用”或完成 403 正反向验收。
- 对 P0 接受的指标口径有实际非零样本，或者明确把 Docker 不支持的 AI Statistics 标成 SKIP/后续，不伪报通过。

风险与依赖：IP CIDR 需要运维确认；P0 默认不擅自启用宽泛私网段。指标方案需要用户确认是否接受 LiteLLM + Envoy 原生能力组合。

### P0-7：实现可审计、可恢复的配置版本和回滚
